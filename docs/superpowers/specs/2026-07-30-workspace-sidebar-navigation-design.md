# Codex 式工作区侧栏与导航稳定性设计

日期：2026-07-30

## 背景

Kimi Code Desktop 0.6.0 已具备工作区、任务、归档、主题和 CLI 更新能力，但当前左侧导航仍以“当前工作区下拉框 + 当前工作区任务列表”为核心。真实环境中工作区记录较多，原生下拉框难以浏览，也无法自然承载工作区级的新建、清除、重命名和任务折叠操作。

本次迭代将侧栏改造成 Codex 式的工作区分组列表，同时修复归档重复加载、任务创建后未切换工作区、异步刷新覆盖新状态、浅色主题文字不可见和整体字号过小等问题。

## 已确认的产品决策

1. 采用“工作区分组 + 任务折叠”的统一侧栏，不再保留“当前工作区”原生下拉框。
2. 已归档任务继续只提供查看、搜索和恢复；本次不实现永久删除，也不实现桌面端隐藏。
3. 清除工作区只调用 Kimi Code 正式工作区注销接口，不删除本地目录或其中任何文件。
4. Windows 优先，所有可中文化的界面文案使用中文。
5. 继续兼容 Kimi Code CLI 0.30.x；仅在本地服务提供对应接口时显示工作区清除、重命名等能力。

## 问题根因

### 归档弹窗重复加载

`ArchivedSessionsDialog` 的打开副作用依赖 `onLoad`，而上层每次渲染都会创建新的包装回调。加载状态变化触发重新渲染后，副作用再次执行，形成重复请求并长期停留在加载状态。

### 新建任务工作区被重置

`NewTaskDialog` 在 `workspaces` 数组变化时重新应用当前工作区。后台刷新会替换数组引用，因此用户在弹窗中选择的工作区会被重置。创建成功后只切换任务，没有同步切换到任务所属工作区。

### 导航状态竞态

工作区、任务、任务快照分别维护；任务事件会直接触发并行概览刷新。旧请求晚于新请求返回时可能覆盖较新的选择状态，造成跳回、不可见任务或短暂冻结。

### 浅色主题覆盖不完整

归档弹窗和部分任务操作组件仍使用深色固定值；部分文字字号和颜色没有走语义变量，导致浅色主题下低对比甚至不可见。

## 信息架构

侧栏自上而下分为五个区域：

1. 品牌与侧栏折叠按钮。
2. 全局操作：新建任务、搜索任务、已归档任务。
3. “项目”标题栏：添加已有工作区、创建新工作区、全部折叠/展开。
4. 可滚动工作区分组列表。
5. 本地服务状态与设置入口。

每个工作区分组包含：

- 展开/折叠按钮；
- 文件夹图标、工作区名称和任务数量；
- 工作区级“新建任务”快捷按钮；
- 更多菜单：在资源管理器中打开、重命名、从列表清除；
- 展开后显示该工作区的任务列表；
- 任务过多时显示“加载更多”。

不再存在全局工作区 `<select>`。

## 导航与选择状态

### 单一选择事务

工作区和任务选择必须成对更新：

- 选择工作区时，如果已有当前任务且属于该工作区则保留；否则选择该工作区最近任务；没有任务则进入工作区空状态。
- 选择任务时，先解析任务所属工作区，再一次性更新工作区和任务。
- 创建或恢复任务后，自动展开目标工作区、切换工作区并选中新任务。
- 清除当前工作区后，选择下一个可见工作区；若不存在则进入无工作区状态。

### 异步刷新协调

概览刷新改为可合并、可丢弃旧结果的协调流程：

- 同一时刻最多一个概览刷新生效；
- 后续刷新请求在当前请求结束后合并执行；
- 每次请求带递增版本号，旧结果不能覆盖新结果；
- 任务实时事件刷新当前任务快照，但工作区/任务概览使用节流刷新；
- 用户显式导航优先级高于后台刷新，后台刷新不得重置用户选择。

## 工作区数据与分页

初始加载工作区目录，并加载足够的最近任务用于恢复当前选择。工作区展开时按 `workspace_id` 请求该工作区任务页：

- 默认页大小 20；
- 使用服务端游标加载更多；
- 工作区分组记录 `loading`、`loaded`、`hasMore`；
- 折叠不会丢弃已加载数据；
- 服务端不支持分页参数时回退到现有全局任务列表并在客户端分组。

折叠状态、最近选择的工作区和侧栏展开状态保存在桌面端 UI 偏好中，不写入项目目录。

## 工作区操作

### 添加已有工作区

使用系统文件夹选择器选择已有目录，调用正式工作区注册接口。成功后自动展开并选中该工作区。

### 创建新工作区

流程：

1. 输入工作区名称；
2. 主进程打开系统目录选择器选择父目录；
3. 主进程校验名称，禁止路径分隔符、`.`、`..` 和 Windows 保留名称；
4. 在选定父目录下创建目录；
5. 注册为 Kimi Code 工作区；
6. 自动展开，并提供“创建第一个任务”。

父目录由主进程文件夹选择器产生，不接受渲染层传入任意绝对目标路径。

### 重命名工作区

只修改 Kimi Code 工作区的显示名称，不重命名本地目录。

### 清除工作区

调用 `DELETE /workspaces/{workspace_id}`。确认弹窗明确说明：

- 从桌面端项目列表移除；
- 本地文件不会删除；
- 已有任务记录不会删除；
- 以后重新添加该目录仍可继续使用。

若 CLI 0.30.x 不支持该接口，菜单项显示不可用说明，不执行文件操作作为替代。

## 新建任务体验

- 点击某个工作区旁的加号时，弹窗锁定该工作区，不再重复选择。
- 点击全局“新建任务”时，使用与应用统一的自定义工作区选择器，不使用原生 `<select>`。
- 弹窗打开后只初始化一次工作区；后台列表刷新不得覆盖用户当前选择。
- 创建按钮进入明确的提交状态，防止重复创建。
- 创建成功后关闭弹窗、展开目标工作区、切换并打开新任务。
- “添加已有工作区”和“创建新工作区”在弹窗内作为次级入口。

## 已归档任务

本次只保留：

- 打开时加载一次；
- 搜索标题、路径和最近请求；
- 恢复任务；
- 恢复成功后自动展开任务所属工作区并打开任务；
- 空状态、错误状态和重试；
- 浅色与深色主题完整适配。

不新增删除、隐藏或直接操作 `~/.kimi-code` 会话文件的功能。

## 视觉系统

### 字号层级

- 辅助标签：10–11px；
- 路径、时间和状态：11–12px；
- 菜单、按钮和侧栏正文：12–13px；
- 任务标题：13px；
- 输入框和主要正文：14px；
- 页面标题：19–22px。

禁止继续新增 7px 或 8px 的用户可读正文。

### 主题变量

侧栏、弹窗和本次触及的组件统一使用语义变量：

- `--surface-primary`
- `--surface-secondary`
- `--surface-elevated`
- `--text-primary`
- `--text-secondary`
- `--text-tertiary`
- `--border-subtle`
- `--border-strong`
- `--selection-active`

浅色主题不再通过零散覆盖修补新增组件。归档弹窗、新建任务弹窗、工作区菜单、确认弹窗必须同时验证浅色和深色。

### 交互细节

- 工作区分组标题保持紧凑但点击区域不少于 32px 高；
- 展开/折叠使用短促过渡，不对长任务列表执行高成本高度动画；
- 工作区菜单使用 Radix 弹出层，与模型菜单保持相同圆角、阴影和键盘导航；
- 加载只在对应分组内显示，不阻塞整个侧栏；
- 当前任务强调弱底色和左侧指示线，不使用大面积高饱和色。

## 兼容与安全边界

- 不修改或重新发布系统 CLI；
- 不直接读取、删除或改写 Kimi Code Session 存储目录；
- 不因工作区清除而删除本地文件；
- 所有文件夹创建和选择操作在主进程执行并校验；
- 不支持的新接口以禁用或降级方式呈现；
- 0.30.x 的工作区、任务、对话和归档恢复能力保持可用。

- 工作区折叠状态在重启后保留；

## 本地分发产物保留策略

本次版本完成 Windows 目录包与安装包验证后，清理 `D:\mydev\kimi-code\desktop\release` 中的旧本地分发产物：

- 只保留按语义版本排序最新的两个完整版本；
- 保留与这两个版本对应的安装包、便携包、校验文件和目录包；
- 删除旧版本目录以及仅属于旧版本的安装包、便携包和 blockmap；
- `win-unpacked` 视为当前构建的临时目录，在确认已复制到当前版本目录后可清理或重建；
- 删除前必须解析并校验绝对路径，目标必须是 `release` 的直接子项；
- 此策略只清理本机生成物，不删除 GitHub Release、Git 标签、分支或源码。
