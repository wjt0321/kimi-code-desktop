# Kimi Code Desktop 能力兼容层与后台任务状态设计

## 背景

Kimi Code Desktop 直接使用系统安装的 Kimi Code CLI，而不是内置或锁定某个 CLI 版本。当前桌面端已经在 CLI 0.30.0 上提供工作区、会话、模型、运行策略、Transcript、工具调用、Diff、审批、问题、计划审查、后台任务等功能；上游 0.31.0 及其后的 `main` 又陆续增加了副模型、自定义 Agent、插件 Agent、非阻塞 TaskOutput 和账号资料接口。

桌面端不能简单把版本号作为唯一判断条件：某些接口在正式版本标签之后才进入 `main`，不同安装来源也可能携带不同能力。因此下一阶段先建设统一的运行时能力检测层，在保持 CLI 0.30 完整可用的前提下，为后续功能提供稳定的渐进启用机制。

## 目标

1. 继续把 CLI 0.30.0 作为最低兼容基线，现有功能不回退。
2. 以实际接口行为检测功能，不把语义版本号当作唯一事实来源。
3. 未支持的功能不显示无效入口，不让用户点击后才发现不可用。
4. 把服务能力、版本和兼容状态以简洁中文呈现在设置页。
5. 改善后台任务的状态表达，兼容 0.30 的旧行为和 0.31 的非阻塞 TaskOutput 行为。
6. 为副模型、账号资料、自定义 Agent 和插件 Agent 预留稳定的能力字段，但本轮不实现这些复杂功能的完整 UI。

## 非目标

本轮明确不做以下事情：

- 不强制用户升级系统 CLI。
- 不自动安装或替换用户的 CLI。
- 不以内置 CLI 取代系统 CLI。
- 不启用或依赖 kap-server 的 `--debug-endpoints`。
- 不自行复制上游的 Agent Markdown、插件清单和 Agent 优先级解析逻辑。
- 不提供尚无稳定公开目录接口的自定义 Agent 选择器。
- 不在本轮加入完整账号中心、副模型编辑器或插件管理器。
- 不修改、提交或推送上游 `MoonshotAI/kimi-code` 仓库。

## 方案选择

采用“能力兼容层优先”方案。

相比直接实现副模型或自定义 Agent，该方案能够先解决所有后续功能都会遇到的版本与接口差异问题。它的可见功能增量较小，但能避免桌面端逐渐积累散落的版本判断、灰色菜单和不可预测的失败路径。

## 架构设计

### 1. 能力模型

在共享契约中增加桌面端能力快照。能力值采用三态，而不是单纯布尔值：

- `supported`：服务已确认支持该能力。
- `unsupported`：服务明确返回路由不存在或协议不支持。
- `unknown`：尚未检测、服务断开、请求超时或发生不能用于判断能力的错误。

首批能力字段：

- `sessionRuntime`：读取和修改会话运行策略。
- `sessionWarnings`：读取会话级警告。
- `transcript`：读取结构化 Transcript。
- `config`：读取与更新全局配置。
- `secondaryModel`：全局配置中的 `secondary_model` 能力。
- `managedUserInfo`：`GET /oauth/userinfo`。
- `promptProfile`：Prompt 的 `profile` 参数。
- `nonBlockingTaskOutput`：新版后台任务即时快照语义。

其中 `secondaryModel`、`managedUserInfo`、`promptProfile` 在本轮只用于能力记录和后续扩展，不直接产生新的主界面菜单。

能力快照同时包含：

- 检测时的 CLI 版本。
- 服务版本（如果 `/meta` 能稳定返回）。
- 最近检测时间。
- 当前是否处于兼容模式。
- 可供日志和测试使用的检测来源，不向普通用户展示底层错误详情。

### 2. 检测原则

检测由 Electron 主进程执行，渲染进程不直接调用 kap-server。

检测时遵循以下规则：

1. 服务进入 `connected` 后执行一次检测。
2. 同一服务生命周期内缓存结果，避免每次打开设置都产生探测请求。
3. 服务停止、失败或重新启动时清空旧快照并重新检测。
4. HTTP 404、明确的未知路由响应或现有 `isUnsupportedCapability` 能识别的协议错误，记为 `unsupported`。
5. 401、未登录、缺少账号令牌等业务响应表示路由存在，因此能力记为 `supported`。
6. 网络错误、服务中断、超时和无法分类的服务错误记为 `unknown`，不能降级成 `unsupported`。
7. 版本号只作为补充线索和显示信息，不覆盖实际接口检测结果。

### 3. 安全探测

能力探测不能产生持久配置变化，也不能创建用户任务。

允许采用只读请求确认的能力：

- `/meta`
- `/config`
- `/oauth/userinfo`

与会话相关的能力优先复用真实会话调用过程中已经获得的结果，不为了检测而创建临时会话。无法安全、准确探测的能力保留为 `unknown`，等待实际调用或未来公开接口确认。

`promptProfile` 和 `nonBlockingTaskOutput` 不发送测试 Prompt。它们可结合服务版本、已出现的协议字段和真实任务事件逐步确认，但不能因为版本号较低就阻断原有功能。

### 4. 主进程与 IPC

主进程新增一个生命周期级能力服务，职责包括：

- 监听本地服务状态。
- 执行和缓存只读探测。
- 合并实际业务调用反馈。
- 对外返回能力快照。
- 在能力快照变化时通知渲染进程。

预加载层仅暴露结构化能力 API，不暴露任意请求能力：

- 获取当前能力快照。
- 订阅能力快照变化。
- 手动重新检测，用于设置页的刷新操作。

所有 IPC 输入输出继续由共享 Zod Schema 校验。

## UI/UX 设计

### 1. 设置页结构

现有“本机运行环境”升级为“版本与兼容性”，保持当前视觉语言，不增加另一个独立系统设置窗口。

显示内容：

- 桌面端版本。
- CLI 版本。
- CLI 命令或可执行文件路径。
- 本地服务状态。
- 服务版本（可获得时）。
- 兼容模式说明。
- 能力摘要。

CLI 0.30 的正常文案示例：

> 当前使用 Kimi Code CLI 0.30.0。桌面端已启用兼容模式，现有任务功能可以正常使用；新版能力会在升级 CLI 后自动出现。

这不是错误状态，不使用红色警告样式。

### 2. 能力摘要

设置页只显示适合用户理解的能力分组，不直接罗列内部接口名称：

- 会话运行控制
- 结构化任务过程
- 后台任务通知
- 新版扩展能力

状态表达：

- 已可用：正常强调色和勾选图标。
- 当前版本未提供：中性文字，不显示为故障。
- 尚未确认：使用“检测中”或“暂未确认”，允许手动刷新。

副模型、账号资料和自定义 Agent 在尚未形成完整产品功能前归入“新版扩展能力”，不显示半成品操作入口。

### 3. 渐进展示规则

- 能力为 `supported` 且对应产品功能已完整实现时，才显示操作入口。
- 能力为 `unsupported` 时隐藏入口。
- 能力为 `unknown` 时不显示破坏性或误导性的入口；设置页可显示“暂未确认”。
- 已经属于 CLI 0.30 基线的现有功能不因探测暂时失败而被突然隐藏，继续使用当前调用时降级逻辑。

## 后台任务状态设计

### 1. 状态语义

桌面端后台任务展示统一为以下用户状态：

- `运行中`：子任务或后台命令仍在执行。
- `已有进展`：获得新的输出快照，但任务尚未结束。
- `等待完成通知`：新版 TaskOutput 已立即返回快照，完成结果将通过后续事件到达。
- `已完成`：收到明确完成状态或终态结果。
- `失败`：收到明确错误终态。
- `已取消`：任务被用户或会话终止。
- `状态未知`：信息不足，不能误报完成。

这些是桌面端展示状态，不修改上游协议。

### 2. 0.30 兼容

CLI 0.30 继续使用当前 Transcript、任务状态和工具结果推断。无法确认终态时保持“运行中”或“状态未知”，不把一次工具返回当作必然完成。

### 3. 0.31 及以后

当观察到非阻塞 TaskOutput 语义时：

- 即时结果作为进展快照追加或更新到任务详情。
- 如果结果明确表示任务仍在运行，展示“等待完成通知”。
- 后续自动通知到达时刷新任务卡片和详情面板。
- 完成通知只更新对应任务，不让整个会话列表产生不必要闪烁。
- 最近更新时间帮助用户判断内容是否仍在更新。

### 4. UI 表现

后台任务卡片和详情面板使用统一状态色：

- 运行/等待：紫蓝强调色和轻量动画。
- 完成：绿色。
- 失败：红色。
- 取消/未知：中性色。

动画只用于当前正在活动的项目，避免任务列表大面积闪烁。

## 错误处理

- 能力探测失败不弹出全局错误 Toast。
- 设置页可显示“部分能力暂未确认”，并提供重新检测。
- 真实用户操作失败仍沿用现有错误反馈。
- 探测日志不得记录访问令牌、API Key、账号敏感信息或完整响应体。
- `/oauth/userinfo` 探测只判断结果类别；本轮不把用户资料存入桌面端持久化存储。

## 数据与隐私

- 能力快照只在当前应用生命周期内缓存。
- 不新增遥测。
- 不上传 CLI 路径、工作区路径或用户资料。
- 不持久化 OAuth 用户信息。
- 日志使用中性、可诊断但不泄露凭据的字段。

## 测试策略

### 主进程

- CLI 0.30 风格服务：新版路由不存在，能力正确标记为不支持，基线功能不受影响。
- CLI 0.31 风格服务：支持的只读接口正确标记为可用。
- `/oauth/userinfo` 返回未登录或 401：能力仍标记为支持。
- 服务超时或断开：能力标记为未知。
- 服务重启：旧快照失效并重新检测。
- 重复读取：同一生命周期不重复产生不必要请求。

### 共享契约与 IPC

- 三态能力 Schema 校验。
- 能力快照 IPC 输入输出校验。
- 非法数据不能进入渲染进程。

### 渲染进程

- CLI 0.30 显示兼容模式但不显示错误警告。
- 能力可用、不可用、未知三种状态文案正确。
- 手动重新检测期间有明确但克制的加载状态。
- 不完整的新功能不产生菜单入口。
- 后台任务的运行、等待通知、完成、失败、取消和未知状态均有稳定展示。

### 回归验证

- 运行完整单元测试。
- 执行 TypeScript 类型检查。
- 构建 Windows 解压版和安装包。
- 使用系统 CLI 0.30.0 做实际冒烟测试。
- 如果本机具备可安全运行的 0.31 环境，再补充新版能力冒烟；没有时以协议测试覆盖，不修改用户的系统 CLI。
- 验证关闭桌面端时仍会确认退出并终止由桌面端启动的 CLI 服务。

## 发布范围

建议本轮发布为 Kimi Code Desktop 0.5.0。

发布说明重点：

- 继续完整兼容 Kimi Code CLI 0.30。
- 新增服务能力自动识别与兼容模式展示。
- 改善后台任务状态和新版通知语义。
- 为后续副模型、账号资料和自定义 Agent 支持奠定基础。

## 后续迭代顺序

完成本设计后，后续功能建议按以下顺序独立设计和交付：

1. 副模型设置与会话警告。
2. 账号资料与用量展示。
3. 等待上游公开稳定 Agent Catalog 接口后实现自定义 Agent 选择。
4. 插件管理与插件 Agent。
5. 更完整的子 Agent 拓扑、状态和结果展示。

每个阶段继续遵守能力检测原则，不降低 CLI 0.30 基线体验。
